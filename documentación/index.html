Arquitectura del Sistema

Diseño modular en capas desacopladas siguiendo las mejores prácticas de Spring Boot

Cuquora CRM implementa una arquitectura monolítica modular diseñada para alta cohesión y bajo acoplamiento. Se compone de un motor Spring Boot 3.3 ejecutándose sobre Java 17/21, persistencia relacional con JPA/Hibernate, motor de plantillas server-side Thymeleaf enriquecido con componentes interactivos JavaScript y estilos CSS desacoplados.

Capa Arquitectónica Componentes Principales Responsabilidad y Tecnologías
Presentación / Vistas Thymeleaf, HTML5 Semántico, CSS3 Vanilla modular Renderizado dinámico de vistas responsivas, modales unificados, selector de franjas horarias y layout adaptativo.
Controladores Web & API BaseController, AppointmentController, InventoryController, CenterApiController Gestión de peticiones HTTP, validación de parámetros, orquestación de sesión HTTP y exposición de endpoints REST JSON con cálculo geográfico Haversine.
Lógica de Negocio (Servicios) AppointmentService, InventoryService, TreatmentService, UserService, NotificationService Validación matemática de disponibilidad de cabinas (intervalos de 30 min), prevención de roturas de stock, emisión de alertas proactivas y encriptación de contraseñas.
Acceso a Datos (Repositorios) Spring Data JPA, CrudRepository / JpaRepository Consultas JPQL optimizadas para búsqueda espacial, filtrado por centro, ordenación cronológica y transacciones atómicas (@Transactional).
Persistencia & Datos PostgreSQL 16 (Producción / Docker) o H2 Database (Desarrollo) Esquema relacional íntegro con claves foráneas en cascada, unicidad de stock por producto/centro y script automatizado init.sql.

Principio de Aislamiento por Sede:

Cada centro de belleza dispone de su propio almacén de inventario y sus propios tratamientos asignados. El catálogo de productos es global, pero las existencias, umbrales y alertas se calculan de manera independiente por cada sede física.

Modelo de Dominio y Entidades

Estructura relacional de base de datos que sustenta la plataforma

🏢 Center (Centros de Belleza)

Representa una sede física. Contiene nombre, dirección física, teléfono, email de contacto y coordenadas geográficas (latitud y longitud) para el cálculo de distancia en tiempo real.

👤 User & Role (Usuarios y Roles)

Entidad de usuarios del sistema. Posee nombre, email único, teléfono, contraseña cifrada en BCrypt y asignación a un Role (CLIENT o WORKER). Los trabajadores se vinculan a un Center.

💆 Treatment (Catálogo de Servicios)

Tratamientos ofrecidos por cada centro. Incluye nombre, descripción, tarifa (€), duración estimada en minutos (30, 45, 60, 90) y tipología (FACIAL, MASAJES, MANICURA_PEDICURA, CORPORAL, etc.).

📦 Product & Inventory (Insumos y Stock)

Product es el catálogo maestro (nombre, descripción, categoría, PVP). Inventory gestiona las existencias en cada sede con restricción de unicidad (center_id, product_id).

📅 Appointment (Citas y Reservas)

Registra el turno acordado. Vincula un dateTime (fecha y hora exacta), un treatment, un center, el client (o datos de invitado guestName/guestPhone), el worker asignado, su estado (PENDING, CONFIRMED, REJECTED) y el workerMessage para feedback médico-estético.

Puesta en Marcha del Proyecto

Instrucciones para levantar la aplicación en entorno local o mediante Docker

Opción A: Ejecución con Docker Compose (Recomendada con PostgreSQL)

Levanta el servidor web Spring Boot y la base de datos PostgreSQL 16 con los datos iniciales de init.sql ya sembrados:

# Clonar el repositorio y situarse en la raíz del proyecto
cd CRM_CBelleza

# Construir y levantar los contenedores en segundo plano
docker-compose up --build -d

# Visualizar logs del servicio web
docker-compose logs -f app

La aplicación estará accesible en: http://localhost:8080

Opción B: Ejecución Local con Maven y Java 17+

# En Windows PowerShell
./mvnw.cmd spring-boot:run

# En Linux / macOS
./mvnw spring-boot:run

Al arrancar localmente sin variables de entorno de PostgreSQL, Spring Boot arrancará con su base de datos en memoria H2 y ejecutará automáticamente DatabaseSeeder.java, precargando los centros, usuarios, citas, catálogo y stock.
